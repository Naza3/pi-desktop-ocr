# 页面参数与升级保留

日期：2026-10-08（北京时间）。任务 PI-OCR-SETTINGS。

用户报告普通重启保留提示词，而直接覆盖安装新版后提示词及部分参数恢复默认。本轮区分了实际落盘数据、界面显示和宿主安装行为。

## 保存范围

`preferences.toml`的`[settings]`继续保存后端类型、API地址、模型ID、提示词、最大输出token、请求超时、导入缩放最长边、实时结果视图、自动加载和记住密钥开关。新增`[ui]`保存图片预览模式和历史结果视图。凭据仅在明确勾选记住时写入独立`credentials.toml`，不进入普通设置或历史。

识别参数旁显示保存状态，并提供“保存设置”按钮。输入停顿后自动保存，离开输入框也会尝试提前保存；关闭或升级前可显式保存并等待成功提示。无效参数或写入失败显示未保存，不把默认值写回覆盖旧文件。强制结束进程不能依赖页面退出阶段的异步请求保证保存。

历史在`history.toml`中独立保存，最多100条，仅含原图名称、识别文字和内部ID。图片与待识别队列不保存。连接面板与参数区的折叠状态不属于识别参数，连接面板仍在成功连接后自动收起。

## 修复内容

- 持久化原先只有内存状态的图片预览模式及历史视图。
- 把保存反馈放到识别参数区域，连接面板收起后仍可看到；提供明确的保存动作。
- 初始数据尚未读取时禁用参数，避免操作默认表单。
- 保存确认后淘汰较早读取的轮询响应，防止旧快照把新提示词显示回旧值。
- 旧设置只补新增UI默认值，原提示词和识别参数保持；新增UI字段放在独立表，旧版仍能读取原参数。

## 升级行为及证据边界

参考PI Desktop源码`779e16d9`：安装目录是`plugins/installed/<id>`，数据目录是`plugins/data/<id>`。覆盖安装替换安装目录，数据目录按同一ID复用。此插件ID始终为`io.github.naza3.pi-desktop-ocr`，本轮不移动或清空历史和设置文件。

已用实际发布的0.1.0与0.1.1包中的CJS入口，在相同临时数据目录依次加载：0.1.0保存多行中文提示词、模型、地址、超时、token预算、缩放及结果视图，0.1.1全部恢复；已有历史保留，加载时未改写preferences.toml。这里的宿主接口与数据路径是明确测试夹具，不是用户Windows上的安装实测。

改动前精准浏览器验证：0.1.1真实renderer、Controller及Store在等待保存后重开页面和重载Store都保留提示词；立即关闭的3次测试也成功，因此没有证据把用户问题归因于650ms自动保存延迟。

另外独立复现了旧轮询晚于保存确认返回时，界面短暂显示旧提示词、磁盘仍保存新提示词的竞态。这证明一个显示错误，不能据此宣称用户电脑上的实际数据丢失原因已确定。
